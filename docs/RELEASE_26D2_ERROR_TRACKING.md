# Release 26D.2 — Error Tracking

**Gate:** D — Observability, Recovery, and Operational Readiness
**Date:** 2024-06-20
**Owner:** Platform Engineering

## Overview

Configure Sentry for centralized error tracking with release tagging, source maps, and clear error ownership to ensure rapid identification and resolution of production issues.

## Objectives

- All unhandled errors captured and reported to Sentry
- Errors tagged with release version, environment, and tenant
- Source maps uploaded for client-side error deobfuscation
- Error ownership assigned to team and individual level

## Sentry Configuration

### Environment Variables

```env
SENTRY_DSN=https://your-dsn@sentry.io/project-id
SENTRY_ENVIRONMENT=production
SENTRY_RELEASE=1.2.3
SENTRY_TRACES_SAMPLE_RATE=0.1
SENTRY_REPLAYS_SESSION_SAMPLE_RATE=0.1
SENTRY_REPLAYS_ERROR_SAMPLE_RATE=1.0
```

### Initialization

```typescript
// src/lib/sentry.ts
import * as Sentry from '@sentry/react';

Sentry.init({
  dsn: import.meta.env.VITE_SENTRY_DSN,
  environment: import.meta.env.VITE_SENTRY_ENVIRONMENT,
  release: import.meta.env.VITE_SENTRY_RELEASE,
  integrations: [
    Sentry.browserTracingIntegration(),
    Sentry.replayIntegration({
      maskAllText: true,
      blockAllMedia: true,
    }),
  ],
  tracesSampleRate: 0.1,
  replaysSessionSampleRate: 0.1,
  replaysOnErrorSampleRate: 1.0,
  beforeSend(event) {
    // Strip PII from error events
    if (event.request?.cookies) {
      delete event.request.cookies;
    }
    return event;
  },
});
```

### Release Creation

- Sentry releases created automatically in CI/CD pipeline
- Each release includes:
  - Git commit SHA
  - Version number
  - Deploy timestamp
  - Associated source maps

### Release Commit

```typescript
// In CI/CD pipeline
SentryCli.init({
  org: 'your-org',
  project: 'adminmate-ai',
  authToken: process.env.SENTRY_AUTH_TOKEN,
});

await SentryCli.releases.newRelease({
  name: `v${version}`,
  version: version,
  references: [{ name: 'refs/heads/main', commit: gitSha }],
});

await SentryCli.releases.uploadSourceMaps({
  release: { name: `v${version}` },
  include: ['dist/assets'],
});
```

## Error Fingerprinting

### Custom Fingerprints

```typescript
// Group errors by feature for better ownership
Sentry.withScope((scope) => {
  scope.setFingerprint(['{{ default }}', command, entity_type]);
  Sentry.captureException(error);
});
```

### Example Fingerprints

| Error Type | Fingerprint Pattern |
|------------|---------------------|
| Database query | `['db', '{{ query }}', '{{ error_type }}']` |
| API call | `['api', '{{ endpoint }}', '{{ status }}']` |
| Validation | `['validation', '{{ field }}', '{{ rule }}']` |
| Auth | `['auth', '{{ action }}', '{{ reason }}']` |

## Error Ownership

### Ownership Matrix

| Error Category | Primary Owner | Escalation |
|---------------|---------------|------------|
| Authentication | @auth-team | @platform-eng |
| Database | @data-team | @platform-eng |
| Payment Processing | @billing-team | @payments-lead |
| File Storage | @infra-team | @platform-eng |
| External API | @integrations-team | @platform-eng |
| UI/Rendering | @frontend-team | @frontend-lead |

### Ownership Rules

1. **Team Tag**: Every error tagged with owning team
2. **Individual Tag**: Critical errors assigned to on-call engineer
3. **Auto-Assignment**: Sentry auto-assigns based on file path patterns
4. **Notification Routing**: Errors notify the correct team via Slack/ PagerDuty

## Alert Configuration

### Critical Alerts (P0)

- `DatabaseConnectionError` — Immediate PagerDuty
- `PaymentProcessingFailure` — Immediate PagerDuty + Slack
- `AuthenticationBypassAttempt` — Immediate Security Team

### High Alerts (P1)

- `APIErrorRate > 5%` — Slack #alerts-high
- `ResponseTimeP99 > 2s` — Slack #alerts-high
- `ErrorSpike (>2x baseline)` — Slack #alerts-high

### Medium Alerts (P2)

- `NewErrorType` — Slack #alerts-medium
- `RecurringWarning` — Slack #alerts-medium

### Low Alerts (P3)

- `DebugLog` — Sentry only (no notifications)
