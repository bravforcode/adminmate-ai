## Bug 2: release26a51 integration tests (11 failures)
**Root Cause**: **Infinite recursion in PostgreSQL RLS functions** causing `stack depth limit exceeded` (54001) and `infinite recursion detected in policy` (42P17) errors.

### Three interrelated issues:

1. **Mutual recursion between `get_user_company_id()` and `safe_user_company_id()`**
   - Migration `20240627000004` rewrote `get_user_company_id()` to call `safe_user_company_id()`
   - Migration `20240627000001` had already made `safe_user_company_id()` call `get_user_company_id()`
   - Result: A→B→A→B→... infinite recursion, exceeded 2048kB stack depth
   - **Fix**: Both functions now query `user_profiles` directly (no function calls)

2. **`profiles_admin` FOR ALL policy on `user_profiles`**
   - The FOR ALL policy included SELECT, so any SELECT on `user_profiles` triggered it
   - The policy called `safe_user_company_id()` which queries `user_profiles` → recursion
   - **Fix**: Removed the admin ALL policy entirely (self-management via `profiles_update_own`)

3. **`profiles_read` policy calling `get_user_company_id()`**
   - Called the function which queries `user_profiles` → recursive RLS evaluation
   - **Fix**: Split into `profiles_own_read` (self) + `profiles_admin_read` (using fixed `safe_user_company_id()`)

**Additional**: Test `beforeAll` didn't seed test companies → FK constraint violations when setting `company_id`.  
**Fix**: Added service-role company seeding to both integration test setups.
